Cache Lab

Five repeatable experiments that turn the cache's behaviour into numbers you can watch. Every figure below covers that run only — the Dashboard's counters are cumulative instead.

Lab 1 — search storm does the database load actually drop?

Fire the same search N times: the first run touches SQLite, every repeat is served from a node.

Lab 2 — point-read storm with per-iteration eviction

Read one key N times. Without eviction every read after the first is a pure hit; with eviction each read pays a database load — and the row survives all of it (evict ≠ delete).

Lab 3 — node failure drill failover and warm-up

Stop a node and keep reading: the RF=2 replica (or the database) answers instead. Start it again and watch it rejoin through STARTING → warm-up → READY.

Lab 4 — eviction burst evict ≠ delete

Write K fresh keys, evict them all from the cache, then read them back: every value reloads from its surviving database row.

Lab 5 — LRU eviction, watched live one node, no hash-ring fan-out

Renders the doubly linked list exactly as the cache holds it: HEAD → most recently used … least recently used → TAIL. A read hops a key to the front; the next overflow drops the node at the tail.

Tip: fill stops at 300 keys, so overflow demos need a small-capacity node — run python main.py --port 8004 --capacity 20 and attach it from the Cluster tab.
