Lab 1 — search storm: prove the database load drops

Fire the same search N times. The first run touches SQLite; every repeat is served from the cache cluster. Watch the two counters diverge — that gap is the load this system took off the database.

Lab 2 — point-read storm with per-iteration eviction

Read one key N times. Without eviction every read after the first is a pure cache hit; with "evict every iteration" each read pays a database load — and the row must survive all of it (evict ≠ delete).

Lab 3 — node failure drill

Stop a node and keep reading: the RF=2 replica (or the database) answers instead. Start it again and watch it rejoin through STARTING → warm-up → READY.

Lab 4 — eviction burst

Write K fresh keys, evict them all from the cache, then read them back: every value reloads from its surviving database row. Compare with "delete from database" in the Inspector — that one leaves nothing to reload.

Lab 5 — LRU eviction, watched live

Drives one node directly — no hash-ring fan-out — and renders its doubly linked list exactly as the cache holds it: HEAD → most recently used … least recently used → TAIL. A read hops a key to the front; the next overflow drops the node at the tail. Writes here are node-local (no database, no replication), which is what keeps the demo deterministic. Tip: the fill preset stops at 300 keys, so overflow demos work best on a small-capacity node — e.g. start one with python main.py --port 8008 --capacity 20; the router attaches to it automatically.
